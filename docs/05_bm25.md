# 05 — BM25 Keyword Search for Codebases

## 1. Why BM25 is Crucial for Code RAG

Dense vector search relies on semantic similarity. However, developers often query exact identifier strings, such as:

> "Where is `JWT_SECRET` used?"
> "Where is `401 Unauthorized` thrown?"

Dense vectors may smooth over exact string representations, ranking vague security passages higher than the exact line where `JWT_SECRET` is defined.

BM25 (Best Matching 25) calculates exact term frequency and inverse document frequency (TF-IDF derivative):

$$\text{Score}(D, Q) = \sum_{i=1}^{n} \text{IDF}(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot \left(1 - b + b \cdot \frac{|D|}{\text{avgdl}}\right)}$$

## 2. Code-Specific Tokenization

Standard whitespace tokenizers fail on code identifiers like `authenticateUser` or `jwt_secret`.

CODETRACE uses `CodeTokenizer`:
1. Splits camelCase (`authenticateUser` $\rightarrow$ `authenticate`, `user`).
2. Splits snake_case (`jwt_secret` $\rightarrow$ `jwt`, `secret`).
3. Strips punctuation while retaining alphanumeric symbols.
